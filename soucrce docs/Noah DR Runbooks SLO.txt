## Service Level Objectives

### 1. API Availability SLO
- **Objective**: 99.95% availability (4.38 hours downtime/year)
- **Measurement**: Ratio of successful requests (non-5xx) to total requests
- **Calculation Window**: 30-day rolling window
- **Error Budget**: 21.9 minutes/month

```yaml
slo:
  name: api-availability
  objective: 99.95
  window: 30d
  indicator:
    ratio:
      good: 
        filter: 'noah_http_requests_total{status!~"5.."}'
      total:
        filter: 'noah_http_requests_total'
```

### 2. API Latency SLO
- **Objective**: 95% of requests < 500ms
- **Measurement**: 95th percentile latency
- **Calculation Window**: 5-minute intervals
- **Error Budget**: 5% of requests can exceed threshold

```yaml
slo:
  name: api-latency
  objective: 95
  window: 5m
  indicator:
    latency:
      histogram: noah_http_request_duration_seconds_bucket
      percentile: 0.95
      threshold: 0.5
```

### 3. Media Processing SLO
- **Objective**: 99% of compression jobs complete within 5 minutes
- **Measurement**: Job completion time from queue to processed
- **Calculation Window**: 24-hour rolling window
- **Error Budget**: 14.4 minutes/day

```yaml
slo:
  name: media-processing
  objective: 99
  window: 24h
  indicator:
    custom:
      good: 'noah_compression_job_duration_seconds{status="success"} < 300'
      total: 'noah_compression_job_total'
```

### 4. Storage Durability SLO
- **Objective**: 99.999999999% (11 nines) durability
- **Measurement**: Successful reads/writes to B2 storage
- **Calculation Window**: Annual
- **Error Budget**: <1 object loss per billion objects/year

## Disaster Recovery Procedures

### Regional Failover Procedure

#### Prerequisites
- Verify primary region is truly unavailable
- Ensure secondary region is healthy
- Notify incident commander

#### Procedure

##### 1. Database Failover (RTO: 5 minutes)
```bash
# Promote read replica in secondary region
aws rds promote-read-replica \
  --db-instance-identifier noah-production-replica-secondary \
  --backup-retention-period 7 \
  --region eu-west-1

# Update connection strings in Kubernetes secrets
kubectl set secret noah-db-secret \
  --from-literal=url="postgresql://user:pass@noah-production-replica-secondary.eu-west-1.rds.amazonaws.com/noah" \
  -n noah-production

# Restart API pods to pick up new connection
kubectl rollout restart deployment/noah-api -n noah-production
```

##### 2. Redis Failover (RTO: 2 minutes)
```bash
# Promote secondary Redis cluster
aws elasticache modify-global-replication-group \
  --global-replication-group-id production-noah \
  --primary-region eu-west-1 \
  --apply-immediately

# Update Redis connection in secrets
kubectl set secret noah-redis-secret \
  --from-literal=url="rediss://noah-production-secondary.cache.amazonaws.com:6379" \
  -n noah-production
```

##### 3. Update DNS (RTO: 3 minutes)
```bash
# Update Route53 to point to secondary region
aws route53 change-resource-record-sets \
  --hosted-zone-id Z1234567890ABC \
  --change-batch file://failover-dns-change.json

# Contents of failover-dns-change.json:
{
  "Changes": [{
    "Action": "UPSERT",
    "ResourceRecordSet": {
      "Name": "api.noah.app",
      "Type": "A",
      "SetIdentifier": "secondary",
      "Failover": "PRIMARY",
      "HealthCheckId": "secondary-health-check-id",
      "AliasTarget": {
        "HostedZoneId": "Z2FDTNDATAQYW2",
        "DNSName": "d1234567890.cloudfront.net",
        "EvaluateTargetHealth": false
      }
    }
  }]
}
```

##### 4. Verify Services
```bash
# Check API health
curl -f https://api.noah.app/health || exit 1

# Verify database connectivity
kubectl exec -it deployment/noah-api -n noah-production -- \
  psql $DATABASE_URL -c "SELECT 1"

# Check Redis connectivity
kubectl exec -it deployment/noah-api -n noah-production -- \
  redis-cli -u $REDIS_URL ping

# Monitor error rates
kubectl logs -f deployment/noah-api -n noah-production | grep ERROR
```

### Data Recovery Procedures

#### Restore from Backup (RPO: 30 minutes)
```bash
# List available backups
aws backup list-recovery-points-by-backup-vault \
  --backup-vault-name noah-production-vault

# Restore database
aws backup start-restore-job \
  --recovery-point-arn "arn:aws:backup:us-east-1:123456789012:recovery-point:1234567" \
  --metadata "BackupVaultName=noah-production-vault" \
  --iam-role-arn "arn:aws:iam::123456789012:role/BackupRestoreRole" \
  --resource-type "RDS"

# Restore from B2 snapshot
b2 sync b2://production-noah-media-assets/backup/ ./restore/

# Verify data integrity
cd restore/
find . -type f -exec sha256sum {} \; | sort | sha256sum
```

#### Point-in-Time Recovery
```bash
# Restore database to specific time
aws rds restore-db-cluster-to-point-in-time \
  --source-db-cluster-identifier noah-production-primary \
  --target-db-cluster-identifier noah-production-pitr \
  --restore-to-time 2024-01-15T10:30:00.000Z

# Verify recovery
psql -h noah-production-pitr.cluster-xxx.us-east-1.rds.amazonaws.com \
  -U noah -d noah -c "SELECT COUNT(*) FROM assets"
```

## Operational Runbooks

### 1. API High Error Rate

**Alert**: NoahAPIHighErrorRate

**Severity**: Critical

**Dashboard**: https://grafana.noah.app/d/noah-api/noah-api-performance

#### Diagnosis Steps
1. Check error logs:
   ```bash
   kubectl logs -l app=noah-api -n noah-production --tail=100 | grep ERROR
   ```

2. Identify error pattern:
   ```bash
   kubectl exec -it deployment/noah-api -n noah-production -- \
     curl -s localhost:9090/metrics | grep noah_http_requests_total | grep 5
   ```

3. Check database connectivity:
   ```bash
   kubectl exec -it deployment/noah-api -n noah-production -- \
     psql $DATABASE_URL -c "SELECT 1"
   ```

4. Verify external dependencies:
   ```bash
   # Check B2 connectivity
   curl -I https://api.backblazeb2.com/b2api/v2/b2_authorize_account
   
   # Check Redis
   kubectl exec -it deployment/noah-api -n noah-production -- \
     redis-cli -u $REDIS_URL ping
   ```

#### Resolution Steps
1. **If database connection issues**:
   ```bash
   # Check connection pool
   kubectl exec -it deployment/noah-api -n noah-production -- \
     psql $DATABASE_URL -c "SELECT count(*) FROM pg_stat_activity"
   
   # Restart connection pool
   kubectl rollout restart deployment/noah-api -n noah-production
   ```

2. **If memory pressure**:
   ```bash
   # Check memory usage
   kubectl top pods -n noah-production | grep noah-api
   
   # Scale horizontally
   kubectl scale deployment/noah-api --replicas=20 -n noah-production
   ```

3. **If external service issues**:
   ```bash
   # Enable circuit breaker
   kubectl set env deployment/noah-api \
     CIRCUIT_BREAKER_ENABLED=true \
     -n noah-production
   ```

### 2. Compression Queue Backlog

**Alert**: NoahCompressionQueueBacklog

**Severity**: Warning

**Dashboard**: https://grafana.noah.app/d/noah-queue/compression-queue

#### Diagnosis Steps
1. Check queue size:
   ```bash
   kubectl exec -it deployment/noah-api -n noah-production -- \
     redis-cli -u $REDIS_URL llen compression:queue
   ```

2. Check worker status:
   ```bash
   kubectl get pods -n noah-production -l app=noah-compression-worker
   kubectl logs -l app=noah-compression-worker -n noah-production --tail=50
   ```

3. Check GPU availability:
   ```bash
   kubectl describe nodes | grep -A5 "nvidia.com/gpu"
   ```

#### Resolution Steps
1. **Scale workers**:
   ```bash
   # Scale CPU workers
   kubectl scale deployment/noah-worker --replicas=10 -n noah-production
   
   # Scale GPU workers
   kubectl scale statefulset/noah-compression-worker --replicas=5 -n noah-production
   ```

2. **Clear stuck jobs**:
   ```bash
   # Identify stuck jobs
   kubectl exec -it deployment/noah-api -n noah-production -- \
     redis-cli -u $REDIS_URL --eval /scripts/find-stuck-jobs.lua
   
   # Requeue stuck jobs
   kubectl exec -it deployment/noah-api -n noah-production -- \
     redis-cli -u $REDIS_URL --eval /scripts/requeue-stuck.lua
   ```

3. **Optimize compression settings**:
   ```bash
   # Reduce quality for faster processing
   kubectl set env deployment/noah-compression-worker \
     COMPRESSION_QUALITY=0.8 \
     COMPRESSION_PRESET=fast \
     -n noah-production
   ```

### 3. Storage Usage High

**Alert**: NoahStorageUsageHigh

**Severity**: Warning

**Dashboard**: https://grafana.noah.app/d/noah-storage/storage-usage

#### Diagnosis Steps
1. Check current usage:
   ```bash
   # B2 usage
   b2 get-bucket noah-production-media-assets | jq '.bucketInfo'
   
   # Database usage
   kubectl exec -it deployment/noah-api -n noah-production -- \
     psql $DATABASE_URL -c "SELECT pg_database_size('noah')"
   ```

2. Identify large files:
   ```bash
   # Find files over 1GB
   b2 ls --long --recursive noah-production-media-assets | \
     awk '$1 > 1073741824 {print $0}'
   ```

3. Check orphaned files:
   ```bash
   kubectl exec -it job/noah-cleanup -n noah-production -- \
     /app/cleanup --dry-run --type=orphaned_files
   ```

#### Resolution Steps
1. **Run cleanup job**:
   ```bash
   # Manual cleanup trigger
   kubectl create job --from=cronjob/noah-cleanup noah-cleanup-manual \
     -n noah-production
   ```

2. **Archive old media**:
   ```bash
   # Move to cold storage
   kubectl exec -it job/noah-archive -n noah-production -- \
     /app/archive --days=90 --destination=glacier
   ```

3. **Increase quota**:
   ```bash
   # Update B2 bucket quota
   b2 update-bucket noah-production-media-assets allPrivate \
     --lifecycle-rules '[{"daysFromUploadingToHiding": 365}]'
   ```

### 4. Database Replication Lag

**Alert**: NoahDatabaseReplicationLag

**Severity**: Critical

**Dashboard**: https://grafana.noah.app/d/noah-db/database-performance

#### Diagnosis Steps
1. Check replication status:
   ```sql
   -- On primary
   SELECT client_addr, state, sent_lsn, write_lsn, flush_lsn, replay_lsn,
          (sent_lsn - replay_lsn) AS lag_bytes
   FROM pg_stat_replication;
   
   -- On replica
   SELECT now() - pg_last_xact_replay_timestamp() AS replication_lag;
   ```

2. Check network latency:
   ```bash
   # From replica region
   ping -c 10 primary-db.us-east-1.rds.amazonaws.com
   ```

3. Check replica performance:
   ```bash
   aws cloudwatch get-metric-statistics \
     --namespace AWS/RDS \
     --metric-name CPUUtilization \
     --dimensions Name=DBInstanceIdentifier,Value=noah-production-replica-secondary \
     --start-time $(date -u -d '1 hour ago' +%Y-%m-%dT%H:%M:%S) \
     --end-time $(date -u +%Y-%m-%dT%H:%M:%S) \
     --period 300 \
     --statistics Average
   ```

#### Resolution Steps
1. **Reduce write load**:
   ```bash
   # Enable write throttling
   kubectl set env deployment/noah-api \
     WRITE_THROTTLE_ENABLED=true \
     WRITE_THROTTLE_RPS=1000 \
     -n noah-production
   ```

2. **Scale up replica**:
   ```bash
   # Increase replica size
   aws rds modify-db-instance \
     --db-instance-identifier noah-production-replica-secondary \
     --db-instance-class db.r6g.4xlarge \
     --apply-immediately
   ```

3. **Optimize replication**:
   ```sql
   -- On primary
   ALTER SYSTEM SET wal_compression = on;
   ALTER SYSTEM SET max_wal_senders = 10;
   ALTER SYSTEM SET wal_sender_timeout = '60s';
   SELECT pg_reload_conf();
   ```

## Incident Response

### Incident Severity Levels

| Level | Description | Response Time | Example |
|-------|-------------|---------------|---------|
| SEV1 | Complete outage | 15 minutes | API down, data loss |
| SEV2 | Major degradation | 30 minutes | 50% error rate, primary DB down |
| SEV3 | Minor degradation | 2 hours | Slow queries, queue backlog |
| SEV4 | No immediate impact | Next business day | Single pod crash, warning alerts |

### Incident Response Process

#### 1. Detection & Alert
- Automated alerts via PagerDuty
- Manual report via #incidents Slack channel
- Customer report via support

#### 2. Initial Response
```bash
# Join incident channel
/incident declare "API experiencing high error rates"

# Assign roles
/incident role commander @john
/incident role tech-lead @sarah
/incident role comms @mike
```

#### 3. Investigation
- Check dashboards: https://grafana.noah.app
- Review recent deployments
- Check external dependencies
- Gather metrics and logs

#### 4. Mitigation
- Implement immediate fix
- Rollback if necessary
- Scale resources
- Enable circuit breakers

#### 5. Communication
- Update status page
- Notify affected customers
- Internal updates every 30 minutes

#### 6. Resolution
- Verify fix is working
- Monitor for 30 minutes
- Update status page
- Close incident

#### 7. Post-Mortem
- Schedule within 48 hours
- No blame culture
- Document timeline
- Identify action items

### Rollback Procedures

#### Application Rollback
```bash
# Get current revision
kubectl rollout history deployment/noah-api -n noah-production

# Rollback to previous version
kubectl rollout undo deployment/noah-api -n noah-production

# Rollback to specific revision
kubectl rollout undo deployment/noah-api --to-revision=42 -n noah-production

# Monitor rollback
kubectl rollout status deployment/noah-api -n noah-production
```

#### Database Migration Rollback
```bash
# Check migration status
kubectl exec -it job/db-migration -n noah-production -- \
  /app/migrate status

# Rollback last migration
kubectl exec -it job/db-migration -n noah-production -- \
  /app/migrate down 1

# Verify schema
kubectl exec -it deployment/noah-api -n noah-production -- \
  psql $DATABASE_URL -c "\dt"
```

## Capacity Planning

### Metrics to Monitor

#### 1. Request Rate Growth
```promql
# Weekly growth rate
(
  sum(rate(noah_http_requests_total[7d]))
  /
  sum(rate(noah_http_requests_total[7d] offset 7d))
) - 1
```

#### 2. Storage Growth
```promql
# Monthly storage growth
increase(noah_storage_bytes_used[30d])
```

#### 3. Database Size
```promql
# Table size growth
pg_table_size_bytes{table="assets"}
```

### Scaling Triggers

| Metric | Threshold | Action |
|--------|-----------|---------|
| CPU Usage | >70% for 15min | Add 2 nodes |
| Memory Usage | >80% for 15min | Add 2 nodes |
| Request Rate | >10k RPS | Add 5 API pods |
| Queue Depth | >5000 | Add 3 workers |
| Storage | >90% | Archive old data |
| DB Connections | >80% | Add read replica |

### Capacity Planning Process

1. **Weekly Review**:
   - Review growth metrics
   - Check resource utilization
   - Identify bottlenecks

2. **Monthly Planning**:
   - Project 3-month growth
   - Plan infrastructure changes
   - Budget review

3. **Quarterly Review**:
   - Architecture review
   - Technology evaluation
   - Cost optimization

## Security Operations

### Security Monitoring

#### 1. Suspicious Activity Detection
```bash
# Check for unusual API patterns
kubectl logs -l app=noah-api -n noah-production | \
  grep -E "rate_limit|unauthorized|forbidden" | \
  awk '{print $1}' | sort | uniq -c | sort -rn | head -20

# Monitor failed auth attempts
kubectl exec -it deployment/noah-api -n noah-production -- \
  redis-cli -u $REDIS_URL --eval /scripts/failed-auth-report.lua
```

#### 2. Security Scanning
```bash
# Run vulnerability scan
trivy image noah/api:latest

# Check for exposed secrets
kubectl get secrets -n noah-production -o json | \
  jq -r '.items[].data | to_entries[] | .value' | \
  while read secret; do
    echo "$secret" | base64 -d | grep -E "(password|key|token)"
  done

# Audit RBAC permissions
kubectl auth can-i --list --as=system:serviceaccount:noah-production:noah-api
```

### Security Incident Response

#### 1. Suspected Breach
```bash
# Isolate affected pods
kubectl label pod $POD_NAME quarantine=true -n noah-production
kubectl patch networkpolicy default-deny -n noah-production \
  --type='json' -p='[{"op": "add", "path": "/spec/podSelector/matchLabels/quarantine", "value": "false"}]'

# Capture pod state
kubectl exec $POD_NAME -n noah-production -- tar czf /tmp/forensics.tar.gz /app /tmp /var/log
kubectl cp noah-production/$POD_NAME:/tmp/forensics.tar.gz ./forensics-$(date +%s).tar.gz

# Rotate credentials
./scripts/rotate-all-secrets.sh
```

#### 2. DDoS Mitigation
```bash
# Enable rate limiting
kubectl patch ingress noah-api-ingress -n noah-production \
  --type='json' -p='[{"op": "add", "path": "/metadata/annotations/nginx.ingress.kubernetes.io~1rate-limit", "value": "100"}]'

# Enable AWS Shield
aws shield associate-drt-role --role-arn arn:aws:iam::123456789012:role/DRTRole

# Scale up capacity
kubectl scale deployment/noah-api --replicas=50 -n noah-production
```

### Compliance Checks

#### 1. Data Retention
```bash
# Verify deletion of expired data
kubectl exec -it job/noah-cleanup -n noah-production -- \
  /app/cleanup --type=expired_data --report-only

# Audit data access logs
aws s3 cp s3://noah-audit-logs/$(date +%Y/%m/%d)/ . --recursive
grep -E "GetObject|PutObject" *.json | jq '.userIdentity.principalId' | sort | uniq -c
```

#### 2. Encryption Verification
```bash
# Check encryption at rest
aws rds describe-db-instances --db-instance-identifier noah-production-primary \
  --query 'DBInstances[0].StorageEncrypted'

# Verify TLS versions
nmap --script ssl-enum-ciphers -p 443 api.noah.app

# Check S3 encryption
aws s3api get-bucket-encryption --bucket noah-production-media-assets
```
